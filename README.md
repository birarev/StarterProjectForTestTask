# Target Rush

Тестовое задание на Unity: реализация инфраструктуры переходов между сценами и небольшой игровой механики с интеграцией в существующую архитектуру проекта.

## Версия Unity

Unity 6000.3.8f1

## Игровая механика

В проекте реализована мини-игра **Target Rush**.

Цель игрока — набрать 10 очков до окончания времени, не потеряв все жизни.

### Правила

- зелёную цель необходимо нажать;
- красную цель необходимо пропустить;
- за успешное нажатие на зелёную цель начисляется 1 очко;
- нажатие на красную цель отнимает 1 жизнь;
- пропуск зелёной цели также отнимает 1 жизнь;
- у игрока 3 жизни;
- на прохождение даётся 30 секунд;
- по мере увеличения счёта цели начинают сменяться быстрее.

Игрок побеждает, набрав 10 очков.

Поражение наступает, если заканчиваются все жизни или время.

После завершения игры можно запустить новую попытку с помощью кнопки `RESTART`.

## Управление

Управление осуществляется мышью через UI.

- `PLAY` — начать игру;
- нажатие на зелёную цель — получить очко;
- красную цель необходимо игнорировать;
- `BACK` — вернуться в главное меню;
- `RESTART` — начать игру заново после победы или поражения.

## Как запустить проект

1. Открыть проект в Unity 6000.3.8f1.
2. Открыть сцену `FirstScene`.
3. Запустить Play Mode.
4. Нажать `PLAY`.
5. После перехода в `SecondScene` начнётся игра.

## Проверка основных сценариев

### Переход между сценами

1. Запустить `FirstScene`.
2. Нажать `PLAY`.
3. Убедиться, что открылась `SecondScene`.
4. Нажать `BACK`.
5. Убедиться, что снова открылась `FirstScene`.
6. Повторить переход несколько раз.

Повторные переходы не должны создавать дублирующиеся Core-объекты или приводить к ошибкам зависимостей.

### Игровая механика

- Нажатие на зелёную цель увеличивает счёт.
- Нажатие на красную цель уменьшает количество жизней.
- Пропуск зелёной цели уменьшает количество жизней.
- Красную цель можно безопасно пропустить.
- При достижении 10 очков отображается экран победы.
- При потере всех жизней или окончании времени отображается экран поражения.
- `RESTART` запускает новую игровую сессию с начальным состоянием.
- `BACK` возвращает пользователя в главное меню.

## Архитектура

Решение расширяет существующую архитектуру стартового проекта.

### Переходы между сценами

Общий механизм переходов реализован в `SceneTransitionService`.

UI-контроллеры не загружают сцены напрямую. Вместо этого они публикуют `LoadSceneEvent` через существующий `EventManager`.

`SceneTransitionService` получает событие и выполняет переход через `ZenjectSceneLoader`.

Таким образом, детали загрузки сцен находятся в Core и не дублируются в UI-компонентах.

### Dependency Injection

Для регистрации зависимостей используется существующий Zenject.

На уровне `ProjectContext` через `CoreProjectInstaller` регистрируются:

- `EventManager`;
- `SceneTransitionService`;
- `UIController`.

Существующие `ProjectContext` и `SceneContext` используются в соответствии с жизненным циклом объектов.

Дополнительные глобальные singleton-объекты или альтернативные DI-контейнеры не добавлялись.

### UI

Используется существующий подход `ScreenView / ScreenController`.

Реализованы два основных UI-состояния:

- `MainMenu` — главное меню;
- `GameHud` — игровой интерфейс.

`CoreSceneInstaller` открывает начальный экран сцены через `OpenScreenEvent`.

### Игровая логика

`TargetRushGame` отвечает за основное состояние игровой сессии:

- счёт;
- жизни;
- таймер;
- условия победы и поражения.

`TargetRushTarget` отвечает за поведение цели:

- случайное положение;
- выбор безопасного или опасного состояния;
- обработку нажатия;
- обработку пропуска зелёной цели;
- постепенное увеличение скорости смены целей.

`GameHudScreenController` связывает игровую механику с UI.
